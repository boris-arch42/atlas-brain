# Manager Playbook — Cadrage V1/V2 (≈ 09/07/2026)

> [!note] Normalisations transcription : « Work » (aussi transcrit « Works »/« Wox » ailleurs) = **plateforme interne ENT** (orthographe exacte à confirmer) · « Tela » = vraisemblablement **Tella** (vidéo async) · « Modpass/Fuefei (Keeper) » = **Keeper** (gestion des secrets) · « CQ » = vraisemblablement **CR** (comptes rendus).

## TL;DR
Roadmap en **deux phases** pour le Manager Playbook : **Core V1 mesurable** centré sur les routines quotidiennes/hebdomadaires, puis **Playbook V2** pour les outils avancés (« second brain » IA, intégrations Work, lifecycle). Principe directeur : **l'adoption est la vraie livraison** — sans adoption, ni performance ni ROI. Modèle opérationnel = **playbook + certification manager + scorecard trimestrielle**, mesure d'adoption portée par **Boris (neutre)** via des **KPI concrets** dans Work. **Zéro nouvelle licence** (outils existants : transcriptions internes, Tella, Slack, Keeper). **Work = source unique de vérité** (dashboard global des projets + base de décisions Kanban). Répartition : **Boris = systèmes/ops/sécurité/outils/mesure ; Alec = culture/vision/leadership/lifecycle** ; templates/CR/Slack co-portés. Échéances : contenu + templates la semaine suivante, **masterclass live managers le 30/07 (~1h30)**, **go-live complet Core V1 + Playbook le 01/09**. Ce cadrage précède la déclinaison équipes actée au [[2026-07-10 - Gouvernance Ops, Conformité & Support Client (Alec x Boris x Sabrina)]].

## 1 — Contexte & objectif
- Frictions opérationnelles : factures impayées, problèmes de suivi/data, **tensions interpersonnelles** ; le quotidien absorbé par l'« extinction d'incendies » et la gestion des états d'âme (Alec).
- Objectif de la session : sortir en **45 min** avec un plan concret — **périmètre V1, responsabilités, date de lancement** (Alec + Boris).

## 2 — Principe directeur : l'adoption est la vraie livraison (Boris)
- Priorité ≠ contenu seul → **adoption réelle par les managers**. Modèle : **playbook + certification + scorecard** pour vérifier l'application des process.
- **Masterclass enregistré + événement de lancement** pour expliquer et nourrir le contenu.

## 3 — Découpage V1 / V2 & règle de tri
- **16 modules potentiels = trop pour une V1** → split **Core V1** / **Playbook V2**.
- **Core V1** : pratiques **quotidiennes et hebdomadaires** (formation d'habitudes). **V2** : « second brain » IA, intégrations plateforme Work, modules de cycle de vie (implémentation plus longue).
- Règle de tri : **fréquence d'usage quotidienne + mesurabilité** (les pratiques deviennent des réflexes).
- Les **deux phases visibles dès le départ** (roadmap expliquant quand/pourquoi la phase 2 s'active) ; **gate = métriques d'adoption validées** en phase 1. **Échec phase 1 → questionne le rôle du manager** (Alec).

## 4 — Contenu Core V1
- Modules proposés : **structuration & animation des réunions**, **rédaction des CR + suivi des décisions**, **communication claire sur Slack**, **procédures de sécurité & confidentialité**.
- Additionnels possibles : **cadences communes, délégation structurée, bibliothèque de templates**.
- ⚠️ Risque : trop de modules dans un masterclass live → adoption réduite, standard brouillé. Succès V1 = pratiques quotidiennes **mesurables** (KPI/scorecards) + itération rapide dès août.

## 5 — Outils & politique de licences ✅
- **Aucune nouvelle licence** : outils internes existants uniquement.
- Transcriptions de réunions + IA → **solutions actuelles** (transcriptions internes rapides). Vidéo async → **Tella** (licence entreprise existante) plutôt que Loom. **Slack** = canal de communication. **Keeper** = gestion des secrets/mots de passe.

## 6 — Centralisation sur Work & répartition
- **Pilotage projet centralisé sur Work = source unique de vérité** pour tous les pôles (Boris + [[Anisse Rbibe]]) ; **dashboard global** : tous les projets, avancement, prochaines étapes (Boris). Pas de nouvel outil.
- **Boris** : systèmes, opérations, sécurité, outils, **mesure**. **Alec** : culture, vision, leadership, contenu **lifecycle manager**. **Co-portés** : templates, CR, notes de réunion, communication Slack.
- **Operating Rhythm** (niveau de rigueur, cadence de revue, analyses requises) : owner **Alec**, co-construction Boris.

## 7 — Templates, certification & cadence standard
- **Boris crée les templates** → co-validation Alec avant adoption.
- **Certification manager** : condition pour être un manager « live » ; intégrée à l'**onboarding futur** des managers ; sous forme de **quiz/certification dans Work** liée au compte du manager. Questions **spécifiques à l'entreprise** (simples mais distinctives) + compétences managériales reliées au masterclass — **pas de quiz trivial** (Alec + Boris).
- **Scorecard trimestrielle** : adhérence aux standards via **auto-évaluation + évaluation externe** ; critères de validation des gates définis par **Boris**.
- **Cadence commune proposée** : 1:1 hebdo · revues de pôle hebdo · revues inter-pôles bimensuelles · business reviews mensuelles.
- **Mesure de l'adoption portée par Boris (neutre)** — pas par les managers de pôle (anti-biais).

## 8 — KPI d'adoption & base de décisions
- **KPI 1** : % réunions avec **CR au format standard** (suivi via Work).
- **KPI 2** : % réunions **< 45 min et < 5 participants** (mesure via plateforme de réunion / IA).
- **KPI 3** : **% de managers certifiés**.
- **KPI 4** : **discipline Slack** (conversations hors Slack, respect des règles).
- Work héberge et fait respecter les **CR standardisés** (chaque réunion = enregistrement accessible aux parties prenantes).
- Suivi additionnel : **nb total de réunions, heures totales en réunion, tendances** (opportunités de réduction — Boris + Alec).
- **Base de décisions Kanban dans Work** : « à décider / en cours / décidé » (éviter de rediscuter les mêmes arbitrages) + mesurer **délai décision→rediscussion** et **décision→implémentation** (métriques : Alec ; implémentation : Boris). 🔗 Reprise côté équipes le 10/07 (base de décisions Works + interface IA).

- **S+1** : rédaction **contenu, templates, scripts détaillés** des modules (async coordonné) — Boris produit aussi un **plan granulaire + critères précis**.
- **S+2** : répétitions, finalisation supports & logistique → masterclasses live **fin juillet**.

- **Go-live complet Core V1 + Playbook : 01/09** (Boris). Périmètre V1 confirmé + stack d'outils canonique + owners confirmés.
